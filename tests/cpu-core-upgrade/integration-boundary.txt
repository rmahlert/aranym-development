Next optional interpreter boundary after the matched-handler milestone
=====================================================================

The differential subset is a validated experiment, not yet an Atari CPU core.
Do not wire legacy.hpp's test aliases into production. In particular, legacy
fault_pc and modern instruction_pc are used differently, and the eight audited
outcomes require explicit integration decisions and complete fault-frame tests.

Candidate next bounded implementation: a separate optional fast-68040 integer
interpreter library/runner, leaving current ARAnyM as the default. Its initial
profile should be no-MMU/JIT-off, with a single coherent pinned generator/table/
register-state family. A build must reject unsupported feature combinations;
unsupported instructions must reach proper guest exceptions before boot can be
claimed. FPU or MMU opcode stubs that abort a test process cannot support EmuTOS
hardware/FPU probing or FreeMiNT, so they are not an acceptable boot milestone.

Concrete interfaces and gates:

1. State and decode
   Current: src/uae_cpu/registers.h, newcpu.h, generated cpuemu/cpufunctbl and the
   src/uae_cpu/Makefile.am host generators. Modern: include/newcpu.h, gencpu.cpp,
   op_smalltbl_41/cpuemu_40.cpp and matching readcpu/table68k. Move from the small
   view to complete SR, banked USP/ISP/MSP, control registers and instruction
   state. Use an explicit architectural view/adapter, not a global struct cast
   or rename. Keep host memory hot paths inline and avoid state copying on each
   guest instruction. The harness's effective PC representation is deliberately
   different from production pc_p/pc_oldp/native-pointer bookkeeping.

2. Execution and IRQ/trace budget
   Existing interpreter loops newcpu.cpp:1421 onward initialize fault_pc before
   dispatch; newcpu.cpp:1289-1410 handles Atari MFP/SCC/VBL/internal IRQ, STOP and
   trace handling. Modern handlers sometimes perform T0 checks internally while
   current ARAnyM schedules them in the outer loop. Define a bounded run/exit
   contract (budget, guest exception, stop/reset/quit, interrupt service) and
   assert no duplicate or missing trace/IRQ acknowledgement. Do not import the
   WinUAE Amiga event/chipset scheduler accidentally.

3. Memory and faults
   Current memory-uae.h and platform signal/MMU glue enforce distinct Atari
   windows/ROM/MMIO and the accepted 32-bit host-window fix. Modern memory/PC
   helpers require an explicit access-size/read-write/execute adapter. Preserve
   side effects and access order. Validate successful and failed stores, stack
   operations, fixup/partial-register changes, privilege and exact format-7
   frames plus RTE restart with independent ISA/hardware-backed expectations.
   The harness's terminal C++ records neither arbitrate real fault PCs nor prove
   either generation's recovery implementation correct. Old/new PC timing may
   both be valid with their matching frame builders; mixing them is dangerous.

4. NatFeat, EmulOp and nested guest execution
   Current gencpu.c private opcodes and newcpu.cpp:997-1150 implement register
   synchronization, supervisor checks, stack arguments and nested m68k_call.
   The existing callback path deliberately avoids compiling temporary guest
   stacks. Preserve D/A/SR/PC/A7 and exception/quit propagation across callbacks.
   Hatari's modern NatFeat table wrappers remain a useful reference, but do not
   implement ARAnyM EmulOp nesting. The harness's four NatFeat stub cases prove
   only that its own synthetic service contract is observable.

5. FPU/MMU and build isolation
   ARAnyM FPU state is separate from modern fpdata/floatx80. Select an explicit
   interpreter representation and validate FPCR/FPSR/exceptions/FSAVE/FRESTORE;
   leave translated FPU disabled. MMU translation/ATC/permissions/writeback and
   full frame behavior form a separate profile/gate. Existing configure rejects
   MMU+JIT; retain that restriction. A separate optional modern core target must
   avoid accidentally linking both global regstruct/CPU-table symbol sets and
   retain the accepted fVDI, networking shutdown and RAM-window source changes.

Why no production optional-core switch is included in this milestone:
Only16 handler families and a small state view are implemented; the complete SR,
guest exception frames/restart, FPU probes and Atari callback/event contracts
above are absent. Adding a configure switch now would advertise a CPU backend
that cannot satisfy those calls. The separate run.py build remains the honest
optional target until a fuller core library actually links and passes gates.

After an optional complete core can boot: hold exact guest image/configuration,
boot selections, CPU/RAM/JIT/FPU settings, fVDI/font/video backend, resolution and
depth constant. Compare the same hashed GEMBench binary with repeated CPU,
memory and graphics results separately. Repeat real HighWire interaction/boot
and clean networking shutdown. Interpreter handler timing is independent of
future native x86/ARM64 JIT performance and cannot establish those gains.

2026-11-08 experimental qualification update
An opt-in platform target now boots one owned EmuTOS1.4/MiNT/XaAES/fVDI7a17
profile and completes actual guest GEMDOS shutdown. It uses modern integer
handlers with original IEEE FPU bodies (explicit runtime selection), real
Atari bus/events/private NatFeats, and the narrow documented discard-frame
read probes. General format7/RTE7/restart, MMU and JIT remain unsupported; these
paths fail closed rather than being treated as prerequisites for reporting this
specific observed boot. No general compatibility, full FPU upgrade or speedup
is inferred. See platform/legacy-fpu-validation.txt and recorded input hashes.
