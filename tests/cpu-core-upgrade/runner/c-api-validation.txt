Experimental C integration ABI
==============================
c-api.h exposes only stdint.h types and C functions, no UAE headers, native
guest pointers, C++ classes or shared regstruct layout. The library includes
c-api.o; an ARAnyM-facing translation unit can include this header alongside
original ARAnyM types without including modern core.hpp or WinUAE headers.
This is a single-instance experimental API: caller must serialize all access.
The busy guard rejects reentry from bus callbacks; it is not a thread lock.

State snapshots explicitly copy D/A/PC, SR,USP/ISP/MSP and all modeled040 control
registers. Export canonicalizes active bank to A7. Import requires active-bank/
A7 consistency and uses the genuine SR helper after setting matching old/new
bank selectors, preserving caller's canonical A7. This is architectural transfer,
not execution of a guest MOVEC. Internal decode/exception/helper state and safety
latches are retained on import; callers cannot clear a fault by importing state.
Reset clears them. No FP arithmetic state or MMU translation is advertised.

Memory uses the bus contract in bus-validation.txt. The C wrapper validates
callback return0/1, contains C++ exceptions and latches unsafe continuation on
host failure. Callback code must not throw through unrelated C/library frames.
get/set/run/config operations return BUSY inside callbacks. Future NatFeat/
EmulOp host service boundaries must run after instruction suspension, not mutate
CPU state from inside a memory callback. These service/Atari adapters are absent.

Typed run and IRQ results distinguish guest exceptions, memory faults, stopped,
budget, unsupported capability, MMU and doublefault. API return status separately
reports argument, busy and host-boundary errors. Custom IRQ vectors are explicit,
independent of priority. No native exception crosses an exported API function.

80 assertions compiled as ordinary C11 and linked with the real C++ generated
library PASS normal and ASan/UBSan: raw MOVEQ/ADDQ/STOP, full field-by-field
snapshot, bank transitions and bad-A7 rejection, bounded run, masked IRQ and
real customIRQ64 frame/RTE, high32bit Cbus program, callback reentry rejection,
invalid callback response containment and reset-required continuation, enabled
translation rejection, null/version/address/width validation and bounded detail
string. No struct-padding/memcmp oracle is used. Actual wrong-register negative
--negative-state returns1; unrelated failures return2. All prior runner suites
remain passing. Same pinned WinUAE source; no production build option or emulator
boot claim. Header/implementation/test are tracked; generated archives ignored.

Next integration gates remain real access-fault restart/writeback and complete
recognized absent-FPU coverage, cache/reset/no-MMU helper contracts, actual
Atari RAM/ROM/MMIO/event/IRQ and NatFeat/EmulOp/nested execution adapters.
