ARAnyM private-instruction service boundary
==========================================
Modern ISA source remains WinUAE d82bc2549f27943d11dc59482d5388daf1c0f337.
ARAnyM-specific platform extensions use original c762046250551840d9c0f32c607713f71a05afa3
generator inputs, verified against Git objects. The builder extracts UNCHANGED
generated op7100/op7101/op7300/op7301 bodies and uses the actual resolved old
decoder. It verifies exactly258words:7100..71ff plus7300/7301. Body hashes and
source pin are recorded separately; these extensions are not attributed to the
public WinUAE ISA table. Generic modern handlers are unchanged.

Private words require explicit platform opt-in. Their real helpers suspend at
a typed HostService boundary with opcode, kind, PC, stack argument addressA7+4
and supervisor state. Suspension precedes the generated post-helper PC advance.
While pending, run returns without another fetch/count/service invocation and
IRQ entry is deferred. External host code can inspect/update the architectural
snapshot. complete_service resumes the SAME generated body with its helper
returning normally; the real generated body advances PC, without another fetch
or guest-instruction count. These private helpers have no architectural reads
or mutations before suspension, as verified by source and tests. This mechanism
must not be generalized to partly executed ordinary instructions.

Actual7100 body enforces supervisor privilege before suspension and has no PC
increment; completion yields HostReturn for eventual nested EmulOp execution.
Other71xx and NatFeat bodies retain their actual increment2. T1 is deferred
until completion, then a real format2 trace frame stores the completed nextPC.
External host reply is not treated as guest instruction execution.

10248 assertions PASS normal+ASan/UBSan: representative privatewords7300/7301/
7101/71ff, user/supervisor modes, all32CCR inputs, exact suspension/PC/stack,
allD/A preservation, host D0 result, no repeat fetch/count, IRQ deferral,
next ordinary instruction, actual7100 privilege and return, opt-in/neighbouring
illegal decode, trace-after-completion and real RTE. --negative-pc corrupts the
expected nextPC; the actual checker rejects only that exact assertion. The pure
C11 suite expands80->90 assertions and exercises the same source continuation
through exported metadata/completion APIs. All previous suites remain passing.

External replies in these tests are MOCKED. This stage does not implement
nf_get_id/nf_call/EmulOp backend behavior or prove real feature lookup, shutdown,
NatFeat exception propagation, nested guest calls or Atari boot. Those require
the actual frontend adapter. C ABI header exposes typed HostService/HostReturn,
private opt-in, get-service and complete-service. It rejects changing pending
PC, disabling pending extensions or completing twice. Architectural state import
does not clear fault/capability latches. Nested service-context management remains
an explicit integration gate; no partly executed MMIO is silently replayed.
