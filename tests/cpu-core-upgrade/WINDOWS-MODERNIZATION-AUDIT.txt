Production dependencies and order

The current native whitelist also excludes imported scalar MUL/EXG and
effective-address/stack/control families, tracked in shin-95jh.3.12. The
inventory lists all imported compiler function headers by mnemonic and the
whitelist difference. A generated function header alone does not establish
successful emission: conditional FAIL paths and no-flags variants must be
qualified. Deliberate upstream interpreter fallbacks do not require inventing
new translators to call the source upgrade complete.

Broader memory JIT must plan every read/write and preserve incoming state
before native execution. Absolute, PC-relative, indexed/indirect, RMW,
MOVEM and implicit stack/control families each need real native execution
witnesses, full state/data/CCR expectations and exact device deoptimization.
The RC2 MOVE guard cannot safely admit those families by changing its table
filter alone: it decodes only top-nibble MOVE and two d16 extension words.

Remaining fault work must retain complete PC, CCR, update/fixup, writeback,
MOVEM and pending trace/IRQ state across actual handler/RTE execution. An
unknown partial device failure must not be retried as if atomic. Locked RMW
and MOVE16 helpers are explicitly absent from the restart extraction.

The modern MMU requires actual upstream translation, page-table descriptor
access/update, ATC and PTEST/PFLUSH interfaces. restart.hpp's get_*_mmu040
names are currently physical aliases, and MMU control enables stop. First
qualify a modern MMU interpreter/OS boot, then define MMU-JIT support; do not
remove configure's MMU rejection over this physical-only adapter.

The modern FPU requires canonical FP registers and pending exception state,
not just new arithmetic functions behind the old IEEE service. The C boundary
currently carries no FP register file. Qualify FPCR/FPSR/FPIAR, rounding,
special values, memory formats and real FSAVE/FRESTORE/FPSP/fault behavior;
then separately qualify modern x64 FPU JIT against that state representation.

The upstream build's FPU closure includes fpp.cpp, fpp_softfloat.cpp,
fpp_native.cpp, softfloat.cpp, softfloat_decimal.cpp and softfloat_fpsp.cpp,
plus matching fpp/softfloat/newcpu types and the FPU JIT compiler. Importing
softfloat.cpp alone omits instruction decode, decimal/FPSP operations and
pending FSAVE data. Conversely, enabling the old native FPU JIT over a new
SoftFloat register bank would combine different state representations.
Select one authoritative canonical FP bank; retain full precision and pending
state when crossing a native-JIT/helper boundary. Test any native cached FP
representation and FP mode conversion explicitly. CPU/FPU snapshot save/load
and version compatibility are also Windows obligations, not only arithmetic.

Nested Atari services are independently unfinished: modern040_execute and
aranym_upstream_modern_step explicitly stop at depth>0. Audit actual m68k_call
and host-service recursion, preserving full core/FPU/restart/banked-stack
state and exact callback counts. Existing paired font boots do not cover all
nested callbacks, enabled FPCR exceptions, traced FPU or FPU operand faults.

State ownership must be explicit before those integrations. The modern core
currently owns restart fixups, MOVEM/trace/service state; the native frontend
owns the old IEEE FPU and integer JIT state. C-ABI setters synchronize only
integer/control registers and intentionally retain nonarchitectural modern
state. A nested callback cannot be fixed by decrementing depth or resetting
the core: it must suspend/restore the outer service and its pending restart,
trace, FPU and exception context while propagating the guest's architectural
callback results exactly once. Reusing physical MMU helper names cannot make
native PC pointers valid under paged translation either; start with a real
modern MMU interpreter boundary before admitting translated logical PCs.

ARM32/AArch64 native backends and Apple platform validation remain genuinely
separate targets. They must not obscure these Windows production gaps.
