Paired no-FPU bootstrap/shutdown fixture
=======================================
The original NOETH.PRG (SHAd2dc467e81e5cb6833b88f676a914341b5b902a270fa264dca31be709936e092)
uses m68020-60 Mintlib CRT. Static symbols/disassembly and actual guest TRAP
trace identify __checkcpu -> .bad881 -> .printexit at runtime01000510/0100051c.
That CRT requires a nonzero _FPU cookie and exits before main on our explicit
absent-FPU LC040 profile. It prints through GEMDOS Cconws, causing the VDI
console banner, then Pterm(-1). This explains the30s fallback-desktop timeout;
no FPU cookie was falsified and the original fixture/result is preserved.

Build a SEPARATELY NAMED same-source fixture for the no-FPU profile:
m68k-atari-mint-gcc -m68000 -msoft-float -O2 -Wall -Wextra -DSTART_NETWORK=0 tests/win-shutdown/guest.c -o /path/owned/NOFP.PRG

Compiler on this host is GCC4.6.4. -m68040 -msoft-float still selects its
m68020-60 hard-FPU CRT; -m68000 selects the default CRT without .bad881.
The test performs ordinary Supexec, real NatFeat feature lookup/STDERR and
NF_SHUTDOWN. START_NETWORK=0 removes receiver start and guest200Hz wait.

No source changes or guest/ROM patches were needed, just the correct runtime.
