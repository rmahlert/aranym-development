Actual private EmulOp direct-exception boundary, 2026-11-08
=========================================================
Ordinary guest source guest/emulop.{c,S} tests every CCR0..31 through the actual
private opcode/host callback path. In user mode it executes original713b JIT
query (returns-1 in noJIT build), records all D/A/CCR/A7, then executes original
supervisor-only712a console EmulOp. Original EmulOp::SUPER_ONLY calls Exception8
directly; no output is permitted in user mode. The guest handler checks real
format0 savedSR/faultPC/vector0020 and enters a supervisor continuation by
controlled frame edit/RTE. It captures user/ISP/D/A before restoring its own
vector/USP/caller stack. It uses ordinary NF_STDERR/NF_EXIT, no debugger or
process-memory access, and does not invoke debugger/CPUdebug EmulOps.

The optional adapter previously assumed every returned non-FPU host function
needed normal service completion. A direct helper Exception had already
cancelled the pending source body, so it failed closed with exit3/"complete
external source body" after entering the guest handler. Fix: record a delivered
exception for ANY pending service, preserve its genuine modern exception target
and skip normal completion after that delivery. Unexceptional private bodies
still resume their original source PC increment once; original FPU bodies still
execute once. No PC normalization, replay or invented instruction body is used.
The pending exception target must match native PC exactly or the adapter stops.
