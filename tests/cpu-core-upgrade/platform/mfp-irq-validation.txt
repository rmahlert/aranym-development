Real Atari MFP master-mode interrupt qualification, 2026-11-08
============================================================
Ordinary guest fixture guest/mfp-irq.{c,S}, soft-float startup. No synthetic
IRQ API, process inspection, debugger, host injection or kernel/image changes.
It derives the existing TimerC vector from MFP VR and current VBR, hooks that
vector while interrupts are masked, executes STOP#3515 (master supervisor,
IPL5 admits MFP6 but masks VBL4), captures the actual interrupt frames, then
chains the unchanged ROM TimerC handler/EOI/RTE. It captures returned SR/A7
before restoring its own vector/MSP/caller stack. Guest verifies exact results
and carries them via NF_EXIT; diagnostics show captured values before cleanup.
The fixture restores the vector and bank, even after a measured frame mismatch.
It relies on ROM-initialized TimerC and is not a general machine exerciser.

Independent architectural expectation: MC68040UM §8.4.1/.2, PDF234. A master
interrupt creates format0 on MSP and throwaway format1 on ISP; format1 RTE
updates SR/bank then resumes processing the real frame. Both PCs denote the
next instruction. TT68K MCP manual record15552d9c559fe4a944ba383bb4ed1a38,
source8082d5f235c8fe79fed877a0, SHAaed5a038586dd2f610068efa01919fc552dc65bfd1a9274a333bad29dbd48894.
Full original evidence read; page234 table previously visually checked.
Only Motorola reference material was queried, no private RTL.

Actual native Linux results, same MFPIRQ.PRG/ROM/config-equivalent fixtures:
- Modern integer d82bc254 + explicitly original IEEE FPU (426a4b9e): exit0.
  Real custom vector69(offset0114), active format1114 on ISP0101e7f6, which
  equals callerISP0101e7fe-8. Saved master format0114 on MSP0100d6f4, which
  equals top0100d6fc-8. Both SR3515, both PC01000a32, matching STOP nextPC.
  Original ROM RTE returns SR3515/A7=mastertop0100d6fc.
- Existing b6735e93 baseline on identical positive guest: exit1. Active
  format0114 is on MSP0100d6f4; no throwaway on ISP. Its MSP register still
  points to top0100d6fc and captured masterframe fields there are zero. Returned
  SR/A7 happen to match, but that does not validate interrupt stack semantics.
  Old Exception source only recognizes vector24..31 for master IRQ framing;
  real MFP TimerC vector69 needs the explicit interrupt identity used by modern
  adapter. This is distinct from the old synchronous M-clear case shin-jug6.
  No production fix/application crash causality claim is made here.
- Deliberately wrong expected format2 (IRQ_EXPECT_FORMAT=0x2000): modernexit1.
  The same actual checker rejects the wrong frame expectation, with no changed
  emulator or architectural IRQ stimulus.
