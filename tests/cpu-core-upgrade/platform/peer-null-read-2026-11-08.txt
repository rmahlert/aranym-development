Instruction/access semantics, not a frame workaround
1210 is genuine generated MOVE.B(A0),D1. The pinned handler reads the source
before setting N/Z/V/C, updating D1 lowbyte or advancing PC; X and upper24D1
are preserved on success. SourceA0 has no postincrement/predecrement. On the
reported failed read there should be no D/A/CCR/PC/bank changes. The original
Atari wrapper's configured PROTECT2K policy denies USER reads below0x800 even
with paged MMU disabled; that is a machine/backend policy, not an assertion
that a bare68040 intrinsically forbids address0. Both frozen Windows configs
have PROTECT2K1/NOCHECKBOUNDARYoff. Modern FC1 request uses that same policy.
Its source access-error gate is intentionally terminal until required genuine
frame/continuation contracts exist; no fake data, replay or implicit skip.
Original ARAM_PAGE_CHECK shortcut is keyed by address without privilege. In
principle cached supervisor low-page access can bypass a later user check;
this source property is NOT established as the observed cause, especially
because the preceding FT_Face load normally uses another data page. Baseline
comparison must distinguish guest bad input, permission-path differences and
actual register/PC divergence before any profile expansion.
