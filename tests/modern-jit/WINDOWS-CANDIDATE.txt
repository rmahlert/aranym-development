Private Windows cross-build of the qualified base JIT
====================================================

This branch starts from fe250a4a (the Linux register/control JIT + genuine
modern040 fallback qualification). The separate scalar-memory pilot is excluded.
Only build/review recipes and metadata are added; native CPU/JIT functional source
matches that protected base. No PE was launched or installed by this recipe.

Build command (all output in an owned directory):
python3 tests/modern-jit/build-windows.py --build-dir /path/owned/windows-build \
  --mingw-root /path/read-only/mingw64 --jpeg-root /path/read-only/jpeg/mingw64 \
  --core-dir /path/copied/windows-core-input

The copied core directory contains the existing pinned Windows modern040 objects,
inputs.json, seed-build-identity.json and matching generated integer.cpp. Source
ABI identities and the d82 seed pin are verified; existing objects/dependencies
are reused. Source and object hashes are captured in windows-jit-build.json.
The generated ARANYMHOME is verified by the target preprocessor as
"aranym-upstream-jit-experimental". Its default profile is separate from the
normal installed ARAnyM profile. Explicit owned test configs remain required.

Static review command (does not execute the target):
python3 tests/modern-jit/review-windows.py --build-dir /path/owned/windows-build \
  --mingw-root /path/read-only/mingw64 --reference-pe /path/existing/private-core.exe

The result is PE32+/AMD64, large-address-aware, native CUI subsystem. The existing
native JIT low-image linker policy is retained: ImageBase10000000, with generated
code/helpers/globals in the intended low-address profile. Target preprocessing
selects ECX/EDX arguments,32-byte Win64 shadow space,16-byte stack alignment and
the Win64 nonvolatile preservation table (plus upstream's extra R11). The direct
DLL import set matches the previously built private modern-core PE exactly.
These source/PE checks establish build selections, not runtime ABI correctness.

windows-jit-static-review.json preserves the actual selected macros/table and
reference DLL comparison. Windows-jit-build.json records the exact binary,
source, copied core objects, compiler/configuration and isolated profile hashes.
The frozen candidate/manifest and qualification commit are preserved outside
tracked source under qualified-windows-candidate. This is a test candidate, not
an installer, release, default update or approval to run against owner images.

Runtime acceptance is pending the root-coordinated Windows smoke handoff and
its guard/matrix review. No new Windows launch is requested by these files.
Expected qualification uses owned64MiB/no-MMU profiles, FixedMemoryOffset60000000,
JITFPUoff, NFETHoff, matching ROM/guest/image/NVRAM hashes and one process at a
time. NoFP first establishes boot/NatFeat/shutdown; hot CCR/register/stack/frame,
IRQ, trace and invalidation guests then establish actual translated TT-RAM and
ABI behavior. A negative fixture must match BOTH guest FAIL marker and intended
exit so an unsupported host exit is not mistaken for a passed negative test.
Full c1 MiNT/fVDI/font/AES and actual Windows/HighWire remain separate gates.
The original IEEE FPU service is explicit for the hard-FPU Mintlib/MiNT fixture;
JIT FPU stays off in both arms. No Windows performance claim has been made.
